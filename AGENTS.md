# Receipt Tracker — инструкции для агента

## Контекст и карта проекта

- Backend для учёта расходов по фотографиям чеков через Telegram. Пока реализован каркас; обработка чеков и интеграция бота ещё не реализованы.
- Стек: NestJS 12, TypeScript, Fastify, TypeORM, PostgreSQL, pnpm. Сборщик Nest CLI — Rspack; линтер — Oxlint, форматтер — Prettier.
- `apps/core` — бизнес-модули и доступ к PostgreSQL через TypeORM.
- `apps/telegram` — взаимодействие с Telegram и обращения к Core; напрямую с БД не работает.
- `apps/*/src/common` — техническая конфигурация и настройки запуска каждого приложения.
- `apps/core/src/infrastructure` — инфраструктура Core, сейчас подключение БД.
- `libs/common` — библиотека общего кода, пока содержит шаблон Nest CLI.
- [Архитектура](docs/architecture.md) — границы приложений, структура и открытые решения.
- [Локальная разработка](docs/development.md) — окружение, запуск, Swagger и проверки.

## Архитектурные правила

- Сохраняй два независимо запускаемых приложения. Транспорт Telegram → Core пока не выбран.
- Бизнес-модули организуем по функциональности; application-слой — сервисы, без отдельных Use Case-классов на старте.
- Не добавляй Gateway, новые сервисы, очереди, брокеры и пустые абстракции без конкретной задачи и принятого решения.
- Сохраняй Fastify и TypeORM. Не переноси Express, Prisma и CQRS из Snaptix автоматически.
- Настройки запуска размещай в `common/setup`, параметры приложения — в `common/config`. Не разращивай `main.ts` и корневые модули.
- В Core подключены Swagger, CORS и глобальный `StandardSchemaValidationPipe`. Shutdown hooks включены в обоих приложениях. Настройка cookies отложена.
- Не включай `synchronize: true`. Стратегию миграций определим при первой задаче на схему БД.

## Работа и проверки

- Перед любыми изменениями сначала объясни, что и зачем предлагаешь изменить, и запроси явное разрешение пользователя. Дождись подтверждения; без него не создавай, не редактируй и не удаляй файлы, не меняй настройки, зависимости или состояние репозитория. Это правило распространяется и на документацию, включая `AGENTS.md`, и на команды, которые записывают файлы. Чтение и анализ без изменений разрешены. Запрос на анализ, ревью или совет не является разрешением на правки.
- Проверяй реальные файлы перед изменениями. Отделяй факты кода, принятые решения и предложения.
- Объясняй по-русски, кратко и понятно. Если задача только на анализ, не меняй файлы.
- Выполняй изменения в рамках запроса, сохраняй чужие правки.
- Не выводи значения секретов и не добавляй их в репозиторий. Секреты хранятся в игнорируемых файлах или переменных окружения.
- Не выполняй commit, push или публикацию без запроса пользователя.
- Для изменений запуска проверяй `pnpm build:core`, `pnpm build:telegram`, `pnpm lint` и соответствующее поведение приложения.
- Модульные тесты: `pnpm test --runInBand`. E2e: `pnpm test:e2e --runInBand`; Core требует тестового окружения БД, которое пока не настроено.
- Не утверждай, что проверки прошли, если они не выполнялись. `pnpm format` изменяет файлы: не запускай массовое форматирование вне задачи.
- Версия NestJS может отличаться от знакомой тебе. Сверяй API с установленными пакетами и [официальной документацией](https://docs.nestjs.com/llms.txt); сначала проверяй штатные возможности NestJS.
